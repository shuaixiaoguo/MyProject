📋 Git + GitHub 完整操作速查手册
🔵阶段一：GitHub 网页端操作（创建空仓库）
登录 GitHub，点击右上角 “+” → New repository。
填写仓库名（如 my-project），描述选填。
⚠️ 关键：千万不要勾选 “Add a README file”、“Add .gitignore” 或 “Choose a license”，必须保持仓库完全空白。
点击 Create repository。
复制页面显示的 SSH 地址（格式：git@github.com:你的用户名/仓库名.git）。

🔵阶段二：本地命令行操作（首次推送）
复制以下代码块，将 你的用户名 和 仓库名 替换成你自己的：
bash
# 1. 进入你的工程文件夹（注意替换成你自己的路径）
cd /d/GXS/work/git
# 2. 初始化本地 Git 仓库
git init
# 3. 关联远程仓库（使用 SSH 地址，免密推送）
git remote add origin git@github.com:你的用户名/仓库名.git
# 4. 添加当前文件夹所有文件到“暂存区”
git add .
# 5. 提交文件到本地仓库（生成版本快照）
git commit -m "first commit"
# 6. 将本地分支重命名为 main（与 GitHub 默认保持一致，可选但推荐）
git branch -M main
# 7. 推送代码到 GitHub（-u 建立本地与远程的追踪关系）
git push -u origin main
如果第 7 步报错 failed to push 或提示 rejected，请看下面的“报错解析”部分。

🔵 阶段三：日常更新代码（每天只用这三步）
bash
# 1. 添加所有修改
git add .
# 2. 提交修改到本地
git commit -m "本次更新的说明"
# 3. 推送到 GitHub
git push

		报错信息										原因											解决方法
fatal: not a git repository						当前文件夹没有初始化								执行 git init
remote origin already exists					已经关联过远程仓库									执行 git remote set-url origin 新地址 覆盖
error: src refspec main does not match any		本地分支叫 master，但推送的是 main					先执行 git branch -M main 重命名，再重新 push
! [rejected] (non-fast-forward)					远程有本地没有的提交（比如建库时点了 README）		方案A（推荐）：执行 git pull origin main --allow-unrelated-histories，合并后再 push。方案B（慎用）：强制覆盖 git push -f origin main
CONFLICT (content)								同一文件的同一行被两个人改了						打开冲突文件，删掉 <<<<<<<、=======、>>>>>>> 标记，保留你想要的内容，保存后执行 git add . → git commit -m "解决冲突" → git push
Permission denied (publickey)					SSH 密钥没配置好									执行 ssh -T git@github.com 测试，如果失败，重新生成密钥并添加到 GitHub Settings → SSH keys
fatal: refusing to merge unrelated histories	本地和远程是两个独立的仓库（都有各自的初始提交）	执行 git pull origin main --allow-unrelated-histories，允许合并不相关的历史

🟣 极简指令流（纯命令，无注释，适合快速粘贴）
如果你已经熟门熟路，直接复制这一串：
首次推送：
bash
git init
git remote add origin git@github.com:你的用户名/仓库名.git
git add .
git commit -m "first commit"
git branch -M main
git push -u origin main
日常更新：
bash
git add .
git commit -m "update"
git push

🔴 紧急回退（下载旧版本代码）
1. 只看一眼旧版本（安全）：
bash
git log --oneline          # 查看版本号
git checkout 版本号          # 切换到旧版本
git checkout main           # 切回最新版本
2. 永久回到旧版本（危险，丢弃之后的所有改动）：
bash
git reset --hard 版本号
git push -f origin main    # 强制推送覆盖远程

⚠️ 最后三条保命提醒
推送前先拉取：养成习惯，每天写代码前先 git pull，能避免 90% 的冲突。
commit 信息写清楚：别只写 update，写 修复登录页面的bug 这种，未来翻日志才看得懂。
看到 MERGING 别慌：说明你在解决冲突，按提示改完文件，执行 git add . 和 git commit 就能解除这个状态。
